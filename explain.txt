`def` means **define a function**.

`try` tells Python:

> "Try to execute this code, but if something goes wrong, don't crash the whole program. Handle the error."

This is useful when working with files because things can go wrong, such as the file not being accessible.


with open(DATA_FILE, "w") as file:

This line opens the file where we want to save the data.

`open()` is a Python function used to open a file.

`DATA_FILE`
This is the variable containing the name/location of the file.

`"w"` means **write mode**.
It means we want to write new information into the file.
Write mode can replace the existing contents of the file.

`as file`
This gives the opened file a temporary name: `file`.

So we can do:
file.write(...)
to put information into it.

`with` makes Python automatically close the file when we're finished with it.
So you don't need:
file.close()

`file.write(name + "\n")`
This writes the user's **name** into the file.

`\n` means **new line**.
So:
name + "\n"
means:
Timi
and then move to the next line.

`file.write(str(balance) + "\n")`
This saves the user's **balance**.

The important part is:
str(balance)

`str()` converts something into a **string/text**.

`for expense in expenses:`
This is a for loop.
It means:

> "Go through every expense inside the `expenses` list, one at a time."

`file.write(...)`
This tells Python:

> "Write the following information into the file."
Everything inside the brackets is what will be saved.

`f"{expense['description']}|"`
This is an **f-string**.
It allows us to put a variable/value directly inside a string.

expense['description']
gets the description from the expense dictionary.

`f"{expense['category']}|"`

This gets the category of the expense.

`f"{expense['amount']}\n"`

This gets the amount spent.

The `|` separates the different pieces of information.

Instead of saving:
Lunch Food 2000

we save:
Lunch|Food|2000

This makes it easier for your program to separate them later.

`print("Data saved successfully.")`

After everything has been written successfully, Python displays:
Data saved successfully.

This lets the user know that their information has been saved.

`except Exception as error:`
This handles errors.
If something goes wrong inside the `try` section, Python comes here.

`Exception` means a general error.

`as error` stores the actual error message inside a variable called `error`.

`print("Error saving data:", error)`
If something goes wrong, the program prints
Error saving data: [the actual error]

`amount = float(input(...))`

`input()`
input("Enter amount to deposit: ₦")

`float()`
float(...)

"5000"

5000.0

5000.50

`<=` means:

This is the **second check**.
`elif` means:

**else if**
So Python first checks the `if`.
If that wasn't true, it checks the `elif`.

"Is the amount the user wants to withdraw greater than their current balance?"

Insufficient balance.

It means:
> "You don't have enough money in your account to withdraw that amount."

`else` means:
> "If none of the conditions above were true, do this."

So we know:
* The amount is **not zero or negative** ✅
* The amount is **not greater than the balance** ✅

`return balance`

Your code has:
if amount <= 0:
    print("Amount must be greater than zero.")

return balance

This is a problem.

Because `return balance` is not indented under the `if`, Python will execute it **every time**, regardless of whether the amount is valid.

So even if the user enters:
Amount: ₦2500

Python will eventually reach:
return balance

and leave the function immediately.

That means the rest of your code won't run.

It won't get to:
if amount > balance:

or:

expenses.append(expense)

or:

balance -= amount

It should be:
if amount <= 0:
    print("Amount must be greater than zero.")
    return balance

Now `return balance` only happens when the amount is invalid.

`if amount > balance:`

This checks whether the expense is **greater than the user's available balance**.
